# תלוש בעברית

אתר שמאפשר להעלות תלוש שכר, סורק אותו (PDF עם טקסט, או תמונה באמצעות OCR בעברית) ומסביר כל סעיף: מה זה ולמה זה מופיע.

## הרצה
```bash
npm install
npm start        # http://localhost:3000
npm test
```

## פיצ'רים
- **הסבר תלוש** (חינם): העלאה, סריקה והסבר לכל סעיף.
- **מחשבון נטו-ברוטו** (חינם): `/calculator.html`. הנתונים השנתיים (מדרגות מס, ביטוח לאומי, שווי נקודה) נמצאים ב-`public/js/tax-core.js` תחת `TAX_DATA`. **צריך לעדכן אותם בתחילת כל שנה ולאמת מול מקור רשמי.**
- **בדיקת נקודות זיכוי** (חינם): `/credits.html`. הכללים מקורבים ומוגדרים באותו קובץ.
- **השוואת תלושים** (Pro): `/compare.html`. החישוב בשרת (`src/compare.js`) ומוגן ב-`requirePro`.
- **מנוי Pro**: `/pricing.html`, `src/billing.js`. Stripe Checkout + Customer Portal, בלי מסד נתונים: עוגייה חתומה (HMAC) עם מזהה לקוח, נבדקת מול Stripe אחת ליום.

## הגדרת תשלומים (Stripe)
0. נדרש חשבון Stripe שתומך בעסק ישראלי (הזמינות בישראל מוגבלת, כדאי לבדוק בהגדרות החשבון). ל**חשבונית מס ישראלית** Stripe לא מספק פתרון: יש לחבר שירות חשבוניות (למשל חשבונית ירוקה / iCount).
1. בחשבון במצב Test: `STRIPE_SECRET_KEY=sk_test_... node scripts/stripe-setup.js` יוצר מוצר, מחיר חודשי בשקלים והגדרות Customer Portal, ומדפיס `STRIPE_PRICE_ID`.
2. להגדיר משתני סביבה לפי `.env.example` (`STRIPE_SECRET_KEY`, `STRIPE_PRICE_ID`, `PRO_TOKEN_SECRET`, `PUBLIC_URL`).
3. בדיקה במצב Test: להריץ עם מפתח `sk_test_`, לבחור "הצטרפות ל-Pro" ולשלם בכרטיס בדיקה `4242 4242 4242 4242` (תוקף עתידי, CVC כלשהו). אחרי החזרה לאתר הדף יופעל המנוי. מעבר ל-Live: להחליף למפתח `sk_live_` ולהריץ שוב את סקריפט ההקמה.
4. לבדיקה מקומית בלי תשלום: `PRO_DEV_UNLOCK=1 npm start` (מושבת ב-production).
5. מגבלה ידועה: אין שחזור גישה אוטומטי במכשיר חדש (הגישה נשמרת בעוגייה). אפשר להוסיף שחזור באימות מייל.

## סרטון ההסבר בדף הבית
סרטון מונפש בן 7 סצנות, בלי קול, עם כתוביות (`public/js/explainer.js`, סגנון ב-`public/css/home.css`, תוכן הסצנות והכתוביות ב-`public/index.html` בתכונות `data-say`). אפשר לכבות כתוביות בנגן.
תמונות הגלריה (`public/img/shot-*.jpg`) הן צילומי מסך מהמוצר עם נתוני דוגמה, וכדאי לצלם מחדש כשהעיצוב משתנה.

## עוזר האתר, צור קשר ומי אנחנו
- **עוזר האתר (צ'אט):** כפתור בפינת המסך בכל עמוד. מבוסס כללים ופועל בדפדפן, בלי לשלוח שאלות לשרת (`public/js/chat-kb.js` לבסיס הידע, `chatbot.js` לממשק). הוא עונה על שאלות שימוש, מסביר מונחי שכר מהמילון ומפנה לשירות לקוחות. להוספת תשובה: להוסיף ערך ל-`INTENTS`.
- **צור קשר:** `/contact.html`. פניות נשמרות מוצפנות במסד (שמירה 12 חודשים) ונשלחות במייל אם הוגדר `SMTP_URL`. הגנות: מלכודת בוטים, מינימום זמן מילוי, הגבלת קצב (5 לשעה), ולידציה בשרת. לקריאת הפניות: `DB_PATH=... DATA_KEY=... node scripts/tickets.js` (וסגירה: `node scripts/tickets.js close <מספר>`).
- **מי אנחנו:** `/about.html`. הפרטים בסוגריים מרובעים (שם עסק, ח.פ., כתובת) צריכים השלמה.

## חשבונות עם הצפנה בצד הלקוח
`/account.html`. ההצפנה מתבצעת בדפדפן (`public/js/vault-crypto.js`):
- סיסמה + אימייל → PBKDF2 (600K) → שני מפתחות: `authKey` (נשלח לשרת, שמגבב אותו שוב ב-scrypt) ו-`wrapKey` (נשאר בדפדפן).
- מפתח כספת אקראי (AES-GCM 256) מוצפן את הנתונים, ושמור בשרת רק **עטוף** (פעם בסיסמה ופעם במפתח שחזור). השרת לא רואה סיסמה, מפתחות או תוכן.
- איפוס סיסמה: קישור במייל + **מפתח שחזור** (נוצר בהרשמה ומוצג פעם אחת). בלי מפתח השחזור הנתונים אבודים, וזו מהות ה-zero-knowledge.
- התחברות: נעילה אחרי 5 כישלונות (15 דקות), סשן `__Host-ps_sess` (HttpOnly, SameSite=Strict), שוויון זמנים לחשבון שלא קיים.
- קישור מנוי Pro לחשבון משחזר Pro אוטומטית בהתחברות (שחזור גישה בכל מכשיר).
- מגבלות: השוואת תלושים (Pro) שולחת את הסכומים המפוענחים לשרת לחישוב בזיכרון בלבד; מפתח הכספת נשמר ב-`sessionStorage` של הלשונית.
- שליחת מיילים (אימות, איפוס, שחזור מנוי) דורשת `SMTP_URL`.

## זכויות ותזכורות
`/rights.html`: חישוב חופשה, הבראה ומחלה לפי ותק, וקובץ יומן `.ics` (נוצר בדפדפן) עם תזכורות חוזרות. הנתונים ב-`RIGHTS_DATA` (`public/js/rights-core.js`) הם הערכה כללית ויש לאמת ולעדכן אותם מדי שנה.

## בוט וואטסאפ (Pro)
מנוי Pro יכול לחבר וואטסאפ בעמוד `/whatsapp.html`, לשלוח לבוט תמונה/PDF של תלוש ולקבל סיכום והתראות על חריגות לעומת חודשים קודמים.

**הקמה (Meta WhatsApp Cloud API):**
1. ב-[Meta for Developers](https://developers.facebook.com) ליצור אפליקציית Business, להוסיף את מוצר WhatsApp ולחבר מספר עסקי.
2. ליצור System User עם אסימון קבוע והרשאת `whatsapp_business_messaging`, ולמלא `WA_PHONE_NUMBER_ID`, `WA_ACCESS_TOKEN`, `WA_BUSINESS_NUMBER`, `WA_APP_SECRET`.
3. להגדיר Webhook בכתובת `https://<הדומיין>/api/whatsapp/webhook` עם `WA_VERIFY_TOKEN`, ולהירשם לשדה `messages`.
4. לייצר `WA_DATA_KEY` (`openssl rand -hex 32`) ולהקצות כרך קבוע ל-`WA_DB_PATH` (ב-Docker: `/data`).
5. אופציונלי: תזכורת חודשית דורשת תבנית הודעה מאושרת ב-Meta (קטגוריית Utility). שם התבנית ב-`WA_REMINDER_TEMPLATE`.

**איך זה עובד:** האתר מנפיק קישור `wa.me` עם הודעת חיבור חתומה וחד-פעמית (30 דקות). שליחתה מהטלפון מוכיחה בעלות על המספר ומקשרת אותו ללקוח ה-Stripe. התלוש נקרא בזיכרון ונמחק; נשמרים רק מספר טלפון מוצפן וסכומים לפי סעיף (עד 12 חודשים). "הפסק" בוואטסאפ או ניתוק באתר מוחקים הכול.

**לפיתוח מקומי בלי Meta:** `PRO_DEV_UNLOCK=1 WA_DEV=1 npm start`. הודעות יוצאות מודפסות לקונסול, ו-`POST /api/whatsapp/dev-inbound {from,text}` מדמה הודעה נכנסת.

**הערות:** האחסון הוא SQLite מובנה (`node:sqlite`, מסומן ניסיוני ב-Node 22). המתזמן מניח מופע שרת יחיד. כדאי לגבות את `WA_DB_PATH` ולשמור את `WA_DATA_KEY` בנפרד: בלעדיו אי אפשר לפענח את הנתונים.

## הקשחת אבטחה (מעבר לבסיס)
- **PDF:** נקרא ב-Worker מבודד (תקרת זיכרון 192MB, 20 שניות) עם `pdfjs-dist` מעודכן ו-`isEvalSupported:false`. הוחלפה ספריית `pdf-parse` שהכילה pdf.js ישן (CVE-2024-4367).
- **תמונות:** בדיקת מימדים מהכותרת (מגבלת 25MP / 12,000px) לפני ה-OCR, נגד פצצות דחיסה.
- **CSRF/Origin:** כל בקשת POST/PUT/DELETE ל-API נדחית אם `Sec-Fetch-Site` חוצה-אתר או `Origin` שונה מה-Host.
- **עוגייה:** `__Host-ps_pro` בפרודקשן (Secure, Path=/, בלי Domain), אסימונים מקושרי-סוג (`t`), והפעלה חד-פעמית של עסקת Stripe (מחיר ומצב מאומתים).
- **שרת:** `slowloris` (headers/request timeouts), תקרת חיבורים, `query parser` פשוט, 404 ללא השתקפות נתיב, שגיאות ללא stack, `security.txt`.
- **SSRF:** הורדת מדיה מוואטסאפ רק מ-HTTPS ולא לכתובות פנימיות/IP, ללא redirect.
- **פיתוח:** דגלי `PRO_DEV_UNLOCK`/`WA_DEV` גורמים לכשל עלייה בסביבת אירוח.
- בדיקות: `test/security.test.js` מכסה את כל אלה. ב-CI: `npm audit` ו-CodeQL. ראו `SECURITY.md` בשורש הריפו.

## אבטחה ופרטיות (מה כבר ממומש)
- קבצים נשמרים **בזיכרון בלבד** (multer memoryStorage), לא נכתבים לדיסק, ולא נרשמים ללוג.
- בדיקת סוג קובץ לפי תוכן (magic bytes), מגבלת גודל 8MB, קובץ אחד לבקשה, עד 6 עמודים ב-PDF.
- Helmet: CSP קפדני (ללא inline script/style), HSTS, `no-referrer`, `frame-ancestors 'none'`.
- הגבלת קצב (20 בקשות / 10 דקות ל-IP) ומגבלת עיבוד מקבילי; `Cache-Control: no-store` על ה-API.
- קבצי השפה של ה-OCR נארזים מקומית, בלי קריאות לרשתות חיצוניות בזמן ריצה.
- כל טקסט שמגיע מה-OCR מוצג ב-`textContent` בלבד (הגנה מפני XSS).

## לפני עלייה לאוויר
- להפעיל מאחורי HTTPS (Nginx / Cloudflare / PaaS) ולהגדיר `TRUST_PROXY=1` ו-`NODE_ENV=production`.
- להשלים פרטים ב-`privacy.html`, `terms.html`, `accessibility.html` (מסומנים בסוגריים מרובעים) ולהעביר לעורך דין.
- לבצע בדיקת נגישות מקצועית (ת"י 5568 / WCAG 2.1 AA) ובדיקת חדירות.
- לוודא שלוגים של שרת/פרוקסי לא שומרים גופי בקשות.
- להשלים את מדיניות ההחזרים והביטולים בתנאי השימוש (חוק הגנת הצרכן) ולעדכן את `TAX_DATA` לשנה הנוכחית.

## מבנה
- `server.js`: שרת Express ו-API (`/api/analyze`, `/api/analyze-text`, `/api/glossary`)
- `src/glossary.js`: מילון המונחים וההסברים (קל להרחבה)
- `src/analyzer.js`: זיהוי סעיפים, סכומים ותובנות
- `src/extract.js`: חילוץ טקסט מ-PDF ו-OCR
- `public/`: ממשק (RTL, מצב כהה/בהיר, תפריט נגישות, רספונסיבי)

## רעיונות להמשך
שחזור מנוי באימות מייל, מנוי שנתי, תזכורות על זכויות (הבראה/חופשה), חשבונות משתמש עם הצפנה בצד לקוח, שפות נוספות.
